# FFmpeg 8.1 "Hoare" リリース徹底解説

**FFmpeg 8.1 "Hoare" は2026年3月16日に正式リリースされた。** 前バージョン FFmpeg 8.0 "Huffman"（2025年8月22日公開）から約7ヶ月ぶりのマイナーリリースであり、**Vulkan コンピュートシェーダによるコーデック最適化**、**D3D12ハードウェアエンコーダの追加**、**JPEG-XS完全サポート**を筆頭に29項目の新機能・改善が盛り込まれた。コードネーム "Hoare" は2026年3月5日に逝去したコンピュータ科学者 Sir Charles Antony Richard Hoare（クイックソートの考案者、1934–2026）に敬意を表して名付けられた。公式アナウンスでは「多数の内部変更とバグ修正を含み、swscale の書き直しの下準備も進行中」と述べられており、ユーザー・ディストリビューター・システムインテグレーターへのアップグレードが推奨されている。

---

## リリース基本情報とライブラリバージョン

FFmpeg 8.1 のリリースブランチは **2026年3月8日**にmasterから切り出され、8日後の3月16日に正式公開された。Gitタグは `n8.1`（コミット `9047fa1b08`）で、Michael Niedermayer 氏がタグ付けを行っている。

ライブラリバージョンは以下のとおりで、8.0からの増分はマイナーバージョンの範囲内に収まっており、**ABIの後方互換性は維持**されている。

| ライブラリ | バージョン |
|---|---|
| libavutil | 60.26.100 |
| libavcodec | 62.28.100 |
| libavformat | 62.12.100 |
| libavdevice | 62.3.100 |
| libavfilter | 11.14.100 |
| libswscale | 9.5.100 |
| libswresample | 6.3.100 |

公式ダウンロードは `ffmpeg-8.1.tar.xz`（および `.tar.bz2`、`.tar.gz`）形式で https://ffmpeg.org/releases/ から入手可能。リリースノートは `https://git.ffmpeg.org/gitweb/ffmpeg.git/blob/refs/heads/release/8.1:/RELEASE_NOTES` で公開されている。

## Vulkan コンピュートの飛躍的進化

今回のリリースで最も注目すべき変更は **Vulkan コンピュートシェーダ関連の大幅な強化**である。具体的には以下の機能が追加・改善された。

**ProRes Vulkan hwaccel（デコード）および ProRes Vulkan エンコーダ**が新たに実装され、Apple ProRes の符号化・復号が完全にGPU上で実行可能になった。従来のCPU/GPUハイブリッド方式ではデータ転送がボトルネックとなっていたが、フルGPUレジデントな処理によりこの問題が解消される。同様に **DPX（Digital Picture Exchange）Vulkan hwaccel** も追加され、映画制作ワークフローで広く使われるDPXファイルのGPUデコードが可能になった。

さらに重要な改善として、**Vulkan コンピュートベースのコーデックおよび一部のフィルタが実行時GLSLコンパイルに依存しなくなった**。これにより初期化時間が大幅に短縮される。公式アナウンスの原文は次のとおり：

> "The Vulkan compute-based codecs, and a few filters, no longer depend on runtime GLSL compilation, which speeds up their initialization."

加えて **swscale Vulkan サポート**が追加され、画像スケーリングをVulkan API経由で実行できるようになった。Khronos公式ブログには「Video Encoding and Decoding with Vulkan Compute Shaders in FFmpeg」と題した技術詳細記事が同時公開され、今後の展望として VC-2、JPEG、APV デコーダのVulkan対応が進行中であること、将来的にJPEG2000やPNGのサポートも検討されていることが明かされている。

## D3D12ハードウェアアクセラレーションの拡充

Windows環境向けのDirect3D 12サポートが大幅に拡充された。**D3D12 H.264エンコーダ**と**D3D12 AV1エンコーダ**が新たに追加され、Windows上でのGPUハードウェアエンコーディングパスが広がった。

フィルタ面では3つの新しいD3D12フィルタが導入されている：

- **vf_scale_d3d12** — D3D12ベースの映像スケーリング
- **vf_mestimate_d3d12** — D3D12ベースのモーション推定
- **vf_deinterlace_d3d12** — D3D12ベースのデインターレース処理

これらにより、GPU上での映像前処理パイプラインがWindowsネイティブに完結できるようになった。GIGAZINEの報道によれば「WindowsベースのGPU処理パスでビデオをより直接的に扱えるようになる」と評されている。

## 新しいデコーダ・エンコーダ・フォーマット

### 音声コーデック

**xHE-AAC Mps212 デコード（実験的）**が追加された。xHE-AAC（Extended High Efficiency AAC）はデジタルラジオやストリーミングの低ビットレート環境で使われるコーデックで、Mps212はそのステレオ拡張パラメトリック符号化モジュールである。現時点では実験的（experimental）フラグ付きの実装だが、将来の安定化が期待される。

**MPEG-H 3D Audio デコード**が外部ライブラリ libmpeghdec 経由で対応した。MPEG-Hは次世代放送やイマーシブオーディオ体験のための3次元音声規格であり、特にATSC 3.0（次世代テレビ放送規格）との関連で重要性が高い。

### 映像コーデック・フォーマット

**JPEG-XS の完全サポート**が実現した。パーサー、libsvtjpegxs を経由したデコーダ・エンコーダ、およびraw bitstreamのマクサー・デマクサーが一挙に追加されている。JPEG-XSは超低遅延・高品質圧縮を特徴とするプロフェッショナル向けコーデックで、放送用IP伝送、VR、ドローン映像、ゲーミングなどの用途に設計されている。Hacker Newsでは映画・TV制作でのカラーグレーディング用途で「**3:1〜4:1の圧縮比で実質的にロスレス**」という実務者の報告や、「H.264/H.265デコードが10フレームのglass-to-glass遅延を持つのに対し、JPEG-XSは**3〜4フレームまで短縮**できる」という証言が寄せられている。ただし特許が存在する点には注意が必要。

**Rockchip H.264/HEVC ハードウェアエンコーダ**も追加された。ARM SoC搭載の組み込みデバイス向けのrkmppベースの実装である。Hacker Newsのコミュニティでは「Rockchipカーネルが必要であり、汎用的なアップストリームソリューションではない」との指摘がある一方、「従来は自分でFFmpegをコンパイルする必要があったため、それでも大きな進歩」との評価もある。

### その他のフォーマット対応

**hxvs デマクサー**がHXVS/HXVT形式のIPカメラ映像に対応した。**IAMF Projection mode Ambisonic Audio Elements** のマクシング・デマクシングも追加され、空間音声（Ambisonics）の処理能力が拡張されている。

## メタデータ・ビットストリームフィルタと新フィルタ

**EXIF メタデータパーシング**が新たにサポートされ、静止画や映像ファイルからの撮影情報・属性の読み取りが可能になった。

**LCEVC（Low Complexity Enhancement Video Coding）**に関連する3つの機能が一括追加されている。LCEVCメタデータビットストリームフィルタ、LCEVCパーサー、およびMPEG-TSにおけるLCEVC拡張レイヤーエクスポートである。LCEVCはISO/IEC 23094-2で標準化された低複雑度の映像品質拡張技術で、既存コーデックの上に薄い拡張レイヤーを重ねることで画質を向上させる仕組みである。

新しいフィルタとしては、**drawvg フィルタ**（libcairo経由）が追加された。これはビデオフレーム上にベクターグラフィックスを描画するフィルタである。また、AMD AMFの**vpp_amfフィルタにHDR処理能力が拡張**された（Extend AMF Color Converter HDR capabilities）。

## CLIツールの改善と削除された機能

ffprobe に **`-codec` オプション**が新設され、デコーダを強制指定するための `-c` のエイリアスとして使える。また、ffprobe は**フレーム読み取り時にのみストリームセクションの refs フィールドを表示**するよう動作が変更された。ffmpeg CLI では**タイル化HEIF（tiled HEIF）のサポート**が追加され、HEIFコンテナの高解像度タイル画像を扱えるようになった。

Windows 環境向けには **gfxcapture**（Windows.Graphics.Capture ベースのウィンドウ/モニターキャプチャ）が新入力デバイスとして追加された。従来のGDI/DXGIキャプチャよりもオーバーヘッドが低く、D3D11ハードウェアフレームとして出力される。Hacker Newsでは「OSS版Discordの代替を開発する計画に大きな影響を与える」というコメントも見られた。

**削除された機能**として、**旧HLSプロトコルハンドラが完全に除去**された。これは以前から非推奨とされていたもので、HLS再生にはデマクサー経由のアクセスが推奨される。

## セキュリティ修正・バグ修正と内部変更

公式アナウンスでは「多数の内部変更とバグ修正（a lot of internal changes and bugfixes）」が含まれると述べられている。8.1はmasterブランチから切り出されているため、**8.0以降にmasterで修正されたすべてのセキュリティ脆弱性が含まれる**。FFmpegのセキュリティページ（ffmpeg.org/security.html）には CVE-2025-0518、CVE-2025-1816、CVE-2025-22919 等を含む複数のCVEが記録されており、これらの修正は8.1に反映済みである。

内部的には**swscale の書き直し（リライト）の下準備が進行中**であることが公表された。swscale は FFmpeg の中核コンポーネントである画像スケーリング・色空間変換ライブラリであり、この書き直しが完了すれば将来的に大幅なパフォーマンス改善が見込まれる。ただし、8.1時点ではまだ「基盤作り（groundwork）」の段階である。

## コミュニティの反応と今後の展望

Hacker Newsでのディスカッション（item #47413525）は**368ポイント・56コメント**を集め、活発な議論が展開された。Phoronix、Linuxiac、9to5Linux、How-To Geek、GIGAZINE、AlternativeTo など多数のメディアが即日〜翌日に報道しており、注目度の高いリリースとなった。

今回のリリースの大きなテーマは**GPU処理パイプラインの成熟**である。Vulkanコンピュートによるコーデック処理、D3D12によるフィルタ処理、Rockchipによるハードウェアエンコードと、多方面でGPUアクセラレーションが拡充された。How-To Geekは「Vulkanベースのエンコーダ・デコーダにより、CPUとGPU間の絶え間ない切り替えではなく、マルチスレッド操作でより多くの処理をGPU上に留められる」と評している。

今後の方向性としては、swscale の完全リライトによる画像処理性能の飛躍、Vulkan対応コーデックのさらなる拡大（VC-2、JPEG、APV、将来的にはJPEG2000・PNG）、そしてxHE-AAC Mps212の安定化が期待される。FFmpegは事実上すべてのマルチメディアアプリケーションの基盤であり、8.1での改善は下流の無数のソフトウェアに波及していく。
